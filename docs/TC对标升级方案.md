# MyExplorer 对标 Total Commander：差距分析与升级方案

> 生成：2026-08-08 · 基于 MyExplorer v1.5.0 代码库实扫
> 目标：把 MyExplorer 打造成 Total Commander 级别的 Windows 双窗格文件管理器

---

## 一、现状盘点（MyExplorer 已有）

| 领域 | 已实现 |
|---|---|
| 布局 | 恒双窗格 + 中间竖快捷栏（16 按钮）+ 每窗格多标签 |
| 视图 | 列表 / 树形 / 网格三视图，每窗格侧边栏（书签/驱动器/树） |
| 快捷栏 | TC 风格 `.bar` 导入（GBK/UTF-8）、图标提取（exe/dll,idx）、CD/cm_ 命令 |
| 文件操作 | 复制/移动/删除/重命名，后台任务面板，冲突对话框，原生复制加速（Rust 核心） |
| 压缩 | zip/tar/tar.gz/tar.bz2/tar.xz 的浏览、解压、压缩（无 RAR/7z） |
| 预览 | Quick Look 弹窗（代码高亮/图片/Markdown/PDF/信息面板） |
| 搜索 | 递归搜索 + 实时过滤 + 通配符选组/取消选组 |
| 批量 | 多重重命名（模板 + 查找替换双模式、token 体系） |
| 比较 | 目录比较模式（compare_controller + diff） |
| 校验 | 单文件校验和验证 |
| 远程 | SFTP 完整读写、SMB 共享发现、WSL 路径 |
| 终端 | 内嵌 PTY 终端（每窗格独立、多标签） |
| 扩展 | FFI 插件系统（自有体系：bar/action/hook） |
| 其他 | 标签系统、隐藏列表、命令面板、文件夹大小扫描、驱动器列表、自动更新、中英双语、主题 |

## 二、差距矩阵（对照 TC 11.5）

### 🔴 核心交互缺失（TC 用户的肌肉记忆区）

| TC 功能 | MyExplorer 状态 | 差距说明 |
|---|---|---|
| **底部 F 键条**（F3查看/F4编辑/F5复制/F6移动/F7建目录/F8删除） | ❌ 无 | 用户明确不做（2026-08-08）：竖快捷栏已集成复制/移动/建目录/删除并新增「查看」按钮，完全替代 F 键条 |
| **底部命令行**（输入命令以当前目录为 cwd 执行，Ctrl+Enter 取选中文件名到命令行） | ❌ 无 | 用户明确不做（2026-08-08）；现有 PTY 终端覆盖命令需求 |
| **快速查看面板 Ctrl+Q**（对侧窗格常驻预览，随选择实时刷新） | ⚠️ Quick Look 是弹窗 | 弹窗需手动关闭打断浏览流；常驻面板可以边按 ↓ 边看内容 |
| **F4 内置编辑器** | ❌ 无 | 用户明确不做（2026-08-08）；依赖外部编辑器 |
| **分支视图 Ctrl+B**（平铺当前目录及所有子目录文件） | ❌ 无 | 用户明确不做（2026-08-08） |

### 🟡 文件操作强化（TC 的可靠性口碑区）

| TC 功能 | MyExplorer 状态 | 差距说明 |
|---|---|---|
| **复制队列**（F5-F2 排队、后台传输管理器） | ⚠️ 有后台任务但无队列编排 | 多任务并行无顺序控制，大量复制时 IO 互踩 |
| **复制后校验**（逐字节比对） | ❌ 无 | 有 checksum_service 基础，缺「复制+校验」组合流程 |
| **校验文件生成**（.md5/.sha1/.sfv 批量生成与批量验证） | ⚠️ 只能单文件验证 | 缺 create .sfv/.md5 文件、批量校验清单 |
| **分割/合并文件**（按大小切割，.001/.002 + .crc） | ❌ 无 | Rust 核心实现成本低 |
| **覆盖策略扩展**（自动重命名旧文件、按日期/大小智能跳过） | ⚠️ 有冲突对话框 | 选项不如 TC 细（如「覆盖较旧文件」「全部跳过相同大小」） |
| **复制限速 / 暂停断点** | ❌ 无 | 大文件拷贝占满 IO 时无法干预 |

### 🟡 搜索与批处理

| TC 功能 | MyExplorer 状态 | 差距说明 |
|---|---|---|
| **重复文件查找**（同大小→同哈希两级比对） | ❌ 无 | checksum_service + folder_size_scanner 都有基础 |
| **全文搜索**（文件内容 grep，支持正则/编码） | ⚠️ 只有文件名搜索 | recursive_search 按名遍历，需加内容匹配层 |
| **搜索结果→供给列表**（feed to listbox，对结果集做批量操作） | ❌ 无 | TC 杀手级工作流：搜完直接全选复制/打包 |
| **多重重命名增强**（正则、计数器 [C]、字段截取 [N1-3]、上级目录名） | ⚠️ 双模式可用 | token 体系少于 TC；正则查找替换需确认 |
| **按扩展名/类型着色**（文件列表彩色规则） | ❌ 无 | 列表渲染单色；TC 用颜色一眼区分可执行/图片/文档 |

### 🟡 归档与虚拟文件系统

| TC 功能 | MyExplorer 状态 | 差距说明 |
|---|---|---|
| **RAR/7z 支持**（7z 经 7za.dll，RAR 经 unrar.dll） | ❌ 仅 zip/tar 系 | 7z 是 Windows 用户刚需；可嵌入 7za 命令行或链接 7-Zip DLL |
| **压缩包内直接浏览/编辑回写**（Enter 进包如进目录） | ⚠️ archive_path 可读 | 缺包内文件编辑后回写、包内搜索 |
| **自解压/分卷压缩** | ❌ 无 | 优先级低 |

### 🟡 远程与协议

| TC 功能 | MyExplorer 状态 | 差距说明 |
|---|---|---|
| **FTP/FTPS 客户端** | ❌ 只有 SFTP | 老旧设备/虚拟主机大量仍是 FTP；可用 Rust `suppaftp` crate |
| **WebDAV** | ❌ 无 | 用户明确不做（2026-08-08） |
| **网络邻居浏览** | ⚠️ SMB 发现 | 已有 smb_share_discovery，可直接挂载体验待验证 |

### 🔵 生态与外围（长期项）

| TC 功能 | MyExplorer 状态 | 差距说明 |
|---|---|---|
| **插件生态**（WCX/WFX/WDX/WLX 四类，数千个现成插件） | ⚠️ 自有 FFI 插件体系 | 无法复用 TC 插件库；自有体系更现代但从零积累 |
| **自定义列**（WDX 内容列：图片尺寸、EXE 版本、媒体时长） | ❌ 无 | 列渲染是固定列；先做内置扩展列（图片尺寸/EXE 版本）再开放 |
| **em_ 用户命令 + 参数化按钮**（%P%N%T%M 参数传递） | ⚠️ 快捷栏无参数宏 | `.bar` 导入时 paramN 里的 %P/%N 未展开成真实路径 |
| **配置导入导出**（wincmd.ini 式） | ⚠️ 设置存 sqlite | 缺一键导出/导入配置文件 |
| **目录热表 Start 菜单**（用户自定义命令菜单） | ⚠️ 书签≠命令菜单 | 可并入书签系统加「命令型书签」 |

## 三、升级方案（五个阶段）

> 原则：先补齐 TC 用户的肌肉记忆（快捷键+快速查看），再强化可靠性口碑（队列+校验），然后做批处理深度，最后扩展生态。每阶段独立可发布。

### Phase 1 — TC 核心交互补齐（约 3 天，v1.6）

> 目标：TC 老用户上手 10 分钟不觉得别扭。

1. **竖快捷栏补「查看」按钮**：对应 TC 的 F3，触发 Quick Look；复用现有 `_openQuickLook`。✅ 2026-08-08 已实现。
2. **快速查看面板 Ctrl+Q**：对侧窗格下半部分显示选中文件预览，随光标移动实时刷新；复用 quick_look 的渲染组件（image/markdown/code/pdf 已齐），只做容器改造。

### Phase 2 — 文件操作可靠性（约 2 周，v1.7）

1. **操作队列**：operation_store 加队列模式，同类 IO 任务串行执行；UI 上任务面板支持排队/暂停/取消。
2. **复制后校验开关**：复制任务完成后对目标逐文件 SHA-1 比对（走 native_copy 的哈希流水线，避免二次读盘）。
3. **分割/合并**：对话框选分割大小（1.44M/100M/700M/自定义），生成 .001/.002…+.crc；合并时校验 crc。
4. **校验文件**：选中多个文件 → 生成 .md5/.sha256 清单；打开清单文件 → 批量验证并出报告。
5. **冲突对话框增强**：加「自动重命名源」「自动重命名目标」「跳过相同大小+日期」三个选项。

### Phase 3 — 搜索与批处理深度（约 2 周，v1.8）

1. **搜索结果供给列表**：搜索结果不再是独立页面，而是灌进当前窗格列表（以「虚拟目录」容器呈现），支持全选后复制/移动/打包/删除。
2. **全文搜索**：recursive_search 加内容匹配（文本文件按块读取 + 正则；可选文件类型过滤 *.cs/*.md）。
3. **重复文件查找**：对话框（扫描范围）→ 大小分组 → 同大小做哈希 → 结果进供给列表，按组着色。
4. **多重重命名增强**：补 [C] 计数器（起始值/步长/位数）、[N1-5] 字段截取、[P] 上级目录名、正则替换模式。
5. **文件着色规则**：设置页加「扩展名 → 颜色」映射表，列表项按规则着色（默认内置：exe 红、图片紫、文档蓝、压缩包棕）。

### Phase 4 — 归档与远程扩展（约 2-3 周，v1.9）

1. **7z 支持**：打包 7za.exe（或链接 7z DLL）进 installer，archive_reader/writer 加 7z 后端；浏览/解压/压缩全通。
2. **包内回写**：编辑压缩包内文本文件保存时重新打包（先支持 zip）。
3. **FTP/FTPS**：waydir_core 加 FTP backend（suppaftp crate），fs_backend 注册协议 `ftp://`；UI 复用 SFTP 的连接对话框。
4. **`.bar` 参数宏展开**：导入 TC `.bar` 时把 `paramN` 里的 `%P`（源路径）`%N`（选中文件名）`%T`（目标路径）`%M` 等在 shortcut_runner 执行前展开——**TC 兼容性最关键的一步**。

### Phase 5 — 打磨与生态（持续，v2.0 方向）

1. **自定义内容列**：先做 3 个内置扩展列（图片尺寸、EXE 版本号、音视频时长），验证列渲染管线的可扩展性，再考虑插件化。
2. **插件市场雏形**：插件清单 JSON（GitHub repo 托管）+ 应用内浏览/安装/卸载；现有 FFI 插件体系加沙箱约束文档。
3. **配置导出/导入**：sqlite 设置 + 快捷栏 + 隐藏列表 + 书签 → 单个 .zip 配置包，一键迁移。
4. **性能专项**：10 万文件目录的滚动流畅度（虚拟列表验证）、大目录着色渲染开销、内存占用审计。
5. **TC 迁移工具**：读取 wincmd.ini + usercmd.ini + .bar，一键导入书签/命令/按钮，降低迁移成本。

## 五、不做清单（明确排除）

1. ❌ 不兼容 TC 原生插件格式（WCX/WFX/WDX/WLX 是 32/64 位 DLL 加 C ABI，绑定成本极高且文档老旧）——走自有插件体系。
2. ❌ 不做并行口/USB 直连线传输（历史功能）。
3. ❌ 不做 Linux/macOS 版（项目定位 Windows-only）。
4. ❌ 不做完整 EXE 反编译级「内嵌查看器插件」（WLX 生态），Quick Look 渲染组件已覆盖主流格式。
5. ❌ **不做底部命令行**（用户 2026-08-08 明确排除；内嵌 PTY 终端已覆盖命令行需求）。
6. ❌ **不做底部 F 键条**（用户 2026-08-08 明确排除；竖快捷栏已集成复制/移动/建目录/删除/查看，完全替代）。
7. ❌ **不做 F4 内置编辑器**（用户 2026-08-08 明确排除；依赖外部编辑器）。
8. ❌ **不做分支视图 Ctrl+B**（用户 2026-08-08 明确排除）。
9. ❌ **不做 WebDAV**（用户 2026-08-08 明确排除）。
